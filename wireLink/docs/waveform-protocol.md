# 故障录波协议解析

本文根据仓库根目录的《故障录波协议说明.pdf》、PDF 中的 Commix 报文截图、厂商补充确认及 WireLink 现有 Modbus RTU 实现整理。录波字节序已由厂商确认为大端；工程量标定和快照一致性等仍是未确认项。本文把已确认事实、报文验证规则和暂定推导分开记录。

## 1. 数据范围

录波区记录故障前 80 ms 到故障后 40 ms 的三相电流采样。每个 20 ms 时间段包含 A、B、C 三个 64 寄存器块，每次 03H 请求读取一个相别，不能一次读取三相。

| 段 | 相对时间 | A 相 | B 相 | C 相 | 每块数量 |
|---:|---|---:|---:|---:|---:|
| 0 | -80 ～ -60 ms | `B000H` | `B040H` | `B080H` | 64 |
| 1 | -60 ～ -40 ms | `B100H` | `B140H` | `B180H` | 64 |
| 2 | -40 ～ -20 ms | `B200H` | `B240H` | `B280H` | 64 |
| 3 | -20 ～ 0 ms | `B300H` | `B340H` | `B380H` | 64 |
| 4 | 0 ～ 20 ms | `B400H` | `B440H` | `B480H` | 64 |
| 5 | 20 ～ 40 ms | `B500H` | `B540H` | `B580H` | 64 |

完整读取需要 18 次请求。每相得到 384 点，三相合计 1152 个采样值。每次请求数量为 `0040H`，正常响应的 byte-count 为 `80H`。三相合计 192 个寄存器，超过 Modbus 03H 单次 125 个寄存器的上限，因此必须分相读取。

地址块之间存在未定义间隔，例如 `B0C0H～B0FFH`。软件只读取表中列出的 18 个块，不把 `B000H～B5BFH` 当作连续有效区间。

## 2. 采样与时间轴

PDF 没有直接给出采样率，但每个 20 ms 时间段有 64 点，因此首版采用以下暂定推导：

```text
采样率 = 64 / 0.020 s = 3200 Hz
采样间隔 = 20 ms / 64 = 0.3125 ms
```

### 2.1 3200 Hz 是怎样算出来的

`3200 Hz` 不是 PDF 直接给出的参数，而是根据“每个 20 ms 时间段有 64 个采样点”推导出来的。采样率的基本计算方法是：

```text
采样率 = 采样点数量 ÷ 采样时间
```

一个录波块包含 64 个采样点，时间长度暂按 20 ms 处理。先把毫秒换算成秒：

```text
20 ms = 0.020 秒
```

代入公式：

```text
64 点 ÷ 0.020 秒 = 3200 点/秒 = 3200 Hz
```

`3200 Hz` 的直观含义是设备每秒采集 3200 个点。相邻两个采样点的时间间隔为：

```text
1000 ms ÷ 3200 = 0.3125 ms
```

也可以从 50 Hz 电网周波理解。50 Hz 的一个完整周波是：

```text
1 ÷ 50 = 0.020 秒 = 20 ms
```

如果一个 20 ms 周波采集 64 点，则：

```text
50 周波/秒 × 64 点/周波 = 3200 点/秒
```

这个结果仍然只是推导，不代表厂商已经正式确认。它成立需要同时满足：

1. 每个地址块的 64 个寄存器就是 64 个独立采样点；
2. 这 64 点均匀覆盖一个 20 ms 时间段；
3. 第一个寄存器对应时间段的起点；
4. 相邻时间块没有重复点或缺失点；
5. 设备没有对原始采样进行隔点、抽样或重新排列。

例如 B200H 暂定对应 `-40～-20 ms`。第一个点的序号按 `i=0` 计算，最后一个点按 `i=63` 计算：

```text
第 1 点：-40 + 0 × 0.3125 = -40.0000 ms
第 2 点：-40 + 1 × 0.3125 = -39.6875 ms
第 64 点：-40 + 63 × 0.3125 = -20.3125 ms
```

下一块 B300H 的第一个点才是 `-20.0000 ms`，因此两个相邻点之间仍相隔 `0.3125 ms`。

厂商仍需明确确认实际采样率、64 点是否完整覆盖 20 ms、块内地址的时间方向，以及相邻块是否连续。如果最终确认的采样率不是 3200 Hz，寄存器原始值不需要改变，但页面曲线和 Excel 中的时间坐标必须重新计算。

### 2.2 每块 64 点是怎样确定的

`64` 不是根据采样率计算出来的，而是由 PDF 中的 Modbus 请求数量、响应字节数和寄存器地址范围共同确定的。

第一种方法是看请求报文。以读取 B200H 为例：

```text
04 03 B2 00 00 40 63 17
```

各字段含义为：

```text
04       从机地址
03       读取保持寄存器
B2 00    起始地址 B200H
00 40    读取数量 0040H
63 17    CRC
```

`0040H` 是十六进制数，换算为十进制：

```text
40H = 4 × 16 + 0 = 64
```

所以请求报文明确要求读取 64 个寄存器。

第二种方法是看响应报文。正常响应开头为：

```text
04 03 80
```

其中 `80H` 是后续有效数据的字节数：

```text
80H = 128 字节
```

每个 Modbus 寄存器占 2 字节，因此：

```text
128 字节 ÷ 2 字节/寄存器 = 64 个寄存器
```

每个寄存器的数据类型是一个 `INT16` 采样值，所以 64 个寄存器对应 64 个采样点。

第三种方法是计算地址范围。以 A 相第一块为例：

```text
B000H～B03FH
```

计算数量时必须同时包含起始地址和结束地址，因此需要加 1：

```text
B03FH - B000H + 1
= 003FH + 1
= 0040H
= 64
```

地址与点号的对应关系是：

```text
B000H  第 1 点
B001H  第 2 点
B002H  第 3 点
……
B03FH  第 64 点
```

三种证据可以相互验证：

```text
请求数量：0040H = 64 个寄存器
响应长度：80H = 128 字节，128 ÷ 2 = 64 个寄存器
地址范围：B000H～B03FH，共 64 个地址
```

因此，“每块 64 点”是协议报文直接确定的；“64 点是否均匀覆盖 20 ms”仍需厂商确认。两者关系为：

```text
协议确定每块有 64 点
PDF 将一个块标记为 20 ms 时间段
        ↓
暂时推导采样率：64 ÷ 0.020 = 3200 Hz
```

时间段按左闭右开处理。段内第 `i` 点的时间为：

```text
t = 段起始时间 + i × 0.3125 ms，i = 0～63
```

全量首点为 `-80 ms`，末点为 `39.6875 ms`。B200H 的首点为 `-40 ms`、末点为 `-20.3125 ms`；B580H 的首点为 `20 ms`、末点为 `39.6875 ms`。

## 3. 数值与端序

PDF 正文写“带符号的 AD 采样值，小端结构”，但 PDF 截图报文与厂商补充确认均表明线路数据采用大端结构。WireLink 固定采用：

1. Modbus 响应内每个寄存器仍按高字节、低字节还原为 `ushort`；
2. 再使用二进制补码转换为 `int16`；
3. 不做额外字节交换。

例如 B200H 响应中的两个值：

```text
1A 30 → 0x1A30 → 6704
FE C0 → 0xFEC0 → -320
```

这样得到的波形连续下降并穿过零点。若交换字节，会得到 `12314` 和 `-16130`，并在相邻点之间产生明显不合理跳变。厂商已确认录波为大端结构，因此 PDF 的“小端”文字不作为线路解析依据；代码不得增加字节交换。

### 3.1 如何判断采样值是负数

有符号的 int16（即 16 位有符号整数）使用补码表示，其取值范围如下：
最大值：32767（即 2^15 - 1，二进制为 0111 1111 1111 1111）
最小值：-32768（即 -2^15 ，二进制为 1000 0000 0000 0000）
录波寄存器的数据类型是 `INT16`，也就是 16 位有符号整数。最简单的判断方法是看组合后的 16 位原始值是否达到 `8000H`：

```text
0000H ～ 7FFFH：0 或正数
8000H ～ FFFFH：负数
```

原因是 16 位数的最高位是符号位。最高位为 `0` 时是非负数，最高位为 `1` 时是负数。常见边界如下：

| 16 位原始值 | 有符号 AD 值 |
|---:|---:|
| `0000H` | 0 |
| `0001H` | 1 |
| `1A30H` | 6704 |
| `7FFFH` | 32767 |
| `8000H` | -32768 |
| `FEC0H` | -320 |
| `FFFFH` | -1 |

如果原始值大于等于 `8000H`，可以用下面的简单公式手工计算：

```text
有符号值 = 原始无符号值 - 65536
```

例如 PDF 的 `FE C0`：

```text
第 1 步：按大端组合字节
FE C0 → FEC0H

第 2 步：判断正负
FEC0H ≥ 8000H，所以是负数

第 3 步：计算负数值
FEC0H = 65216
65216 - 65536 = -320

最终结果：FE C0 → FEC0H → -320 AD
```

另一个最简单的例子是：

```text
FF FF → FFFFH → 65535 - 65536 → -1 AD
```

WireLink 使用 C# 的 `short` 完成同样的二进制补码解释：

```csharp
public static short DecodeSigned(ushort value) => unchecked((short)value);
```

为了便于理解，上述代码也可以等价地写成：

```csharp
public static int DecodeSigned(ushort value)
{
    if (value >= 0x8000)
        return value - 65536;

    return value;
}
```

需要特别区分两个步骤：

1. **大端**决定如何把线路上的两个字节组合成一个 16 位原始值，例如 `FE C0 → FEC0H`；
2. **INT16**决定如何解释这个 16 位值的正负，例如 `FEC0H → -320`。

`Shift+F8` 录波原始点明细窗口同时显示三种形式：“原值（hex）”显示 `FEC0H`，“原值（dec）”显示未转换的 `65216`，“值（AD）”显示有符号结果 `-320`，便于逐点核对。明细窗口的“原始值画图”按钮使用 `0～65535` 的十进制原始值绘图，不执行 `int16` 转换，因此原有负数会出现在接近 65535 的区域。

模拟器直接使用这 18 帧中的 1152 个采样值，不再生成正弦或其他人工波形。PDF 最后一张组合曲线可用于肉眼比对整体形态，但像素图无法作为精确数值来源；开发、测试和导出均以带 CRC 的原始数据帧为准。

## 5. RMS

PDF 给出的离散采样 RMS 公式为：

```text
RMS = sqrt(sum(sample[i]^2) / N)
```

WireLink 对每相完整 384 点分别计算 RMS。累加使用 `double`，不能使用 `int`，以免 384 个 `int16` 平方后溢出。由于协议未提供 AD 到安培的标定公式，页面和 Excel 统一标记为 `AD` 与 `AD-RMS`，不得显示成安培。公式的直观解释、逐步算例、代码关系和窗口选择见 [录波 RMS 公式与解析代码说明](waveform-rms-explained.md)。

## 6. 读取和失败规则

- 按时间段顺序读取，每段依次 A、B、C，共 18 次请求。
- 所有请求复用 `IModbusRtuClient` 的全局请求锁、静默间隔、CRC 和超时重试规则。
- 一个块必须恰好返回 64 个寄存器。
- 任一块最终失败，本次录波整体失败；不得把部分新数据与上次成功数据拼接。
- 页面可以保留上一次完整录波，但必须明确提示本次失败块的相别、时间段和地址。
- 日志记录每块的地址范围、相别、时间段、首尾值和进度。

## 7. 尚未确认的协议项

以下规则不能从 PDF 中可靠确定：

1. AD 到安培的标定比例、零偏和量程；
2. 是否存在多条录波及如何选择；
3. 数据有效标志、准备状态、录波编号或快照版本；
4. 18 次读取期间设备是否保证录波区冻结；
5. 3200 Hz 和左闭右开时间轴是否为设备正式定义；
6. 无录波数据时返回零、异常响应还是旧数据；
7. PDF 组合曲线在块边界处的突变是否来自真实故障或跨块一致性问题；模拟器会忠实保留这些原始采样值，不做平滑修正。

实机验收必须保存原始 TX/RX 日志，对上述项目逐项确认。确认前，软件保留原始 AD 值和源地址以确保数据可追溯。
