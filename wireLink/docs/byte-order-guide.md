# 高字节、低字节与大小端说明

本文解释高字节、低字节、大端、小端、位序和寄存器字序，并结合 WireLink 的 Modbus RTU 实现说明这些概念在线路、协议和代码中的具体表现。

相关文档：[链路层数据包、03H 读数据寄存器与代码实现](link-layer-and-read-register.md)。

## 1. 从二进制位、字节和整数开始

### 1.1 bit

bit（位）是最小的二进制单位，只能是 `0` 或 `1`。

一个 bit 在整数中有不同权重。以 8 位数为例：

```text
bit位置： bit7 bit6 bit5 bit4 bit3 bit2 bit1 bit0
权重：     128   64   32   16    8    4    2    1
```

`bit0` 权重最低，称为最低有效位，即 LSB（Least Significant Bit）；`bit7` 权重最高，称为最高有效位，即 MSB（Most Significant Bit）。

### 1.2 byte

1 byte（字节）通常由 8 bit 组成，可表示：

```text
二进制：00000000 ～ 11111111
十六进制：00H ～ FFH
无符号十进制：0 ～ 255
```

十六进制的两位刚好表示一个字节：

```text
12H = 0001 0010
ABH = 1010 1011
FFH = 1111 1111
```

### 1.3 多字节整数

一个字节最多表示 255。更大的整数需要多个字节：

| 整数宽度 | 字节数 | 十六进制位数 | 无符号范围 |
|---:|---:|---:|---:|
| 8 bit | 1 | 2 | 0～255 |
| 16 bit | 2 | 4 | 0～65535 |
| 32 bit | 4 | 8 | 0～4294967295 |
| 64 bit | 8 | 16 | 0～18446744073709551615 |

只有当一个值占用两个或更多字节时，才需要说明这些字节的排列顺序。

## 2. 什么是高字节和低字节

对于一个 16 位整数：

```text
数值：0x1234
二进制：0001 0010 0011 0100
        └── 12 ──┘└── 34 ──┘
          高字节     低字节
```

- **高字节**：保存数值的高 8 位，权重较高，此处为 `12H`。
- **低字节**：保存数值的低 8 位，权重较低，此处为 `34H`。

“高”和“低”描述的是它们在**数值中的权重**，不是它们在内存、数组或报文中的位置。

### 2.1 提取高、低字节

对于 `value = 0x1234`：

```text
高字节 = (value >> 8) & 0xFF = 0x12
低字节 = value & 0xFF        = 0x34
```

C# 示例：

```csharp
ushort value = 0x1234;
byte highByte = (byte)(value >> 8);   // 0x12
byte lowByte = (byte)(value & 0xFF);  // 0x34
```

### 2.2 从高、低字节恢复整数

```text
value = (高字节 << 8) | 低字节
      = (0x12 << 8) | 0x34
      = 0x1200 | 0x0034
      = 0x1234
```

C# 示例：

```csharp
byte highByte = 0x12;
byte lowByte = 0x34;
ushort value = (ushort)((highByte << 8) | lowByte); // 0x1234
```

## 3. 什么是大端和小端

大端和小端决定一个多字节整数的各个字节按什么顺序存放或传输。

仍以 16 位数 `0x1234` 为例：

| 字节序 | 第一个字节 | 第二个字节 | 记忆方式 |
|---|---:|---:|---|
| 大端 Big-endian | `12H` | `34H` | 高字节在前 |
| 小端 Little-endian | `34H` | `12H` | 低字节在前 |

```text
原数值：0x1234

大端：12 34
      ↑  ↑
      高 低

小端：34 12
      ↑  ↑
      低 高
```

### 3.1 大端为什么叫“大端”

“大”指较高权重的一端。大端把最高有效字节放在较小的地址或报文中较早的位置。

```text
地址/偏移：  0     1
大端内容：  12    34
```

十六进制书写通常也是高位在左，因此大端字节序和人们书写整数的顺序一致：

```text
整数写作 0x1234
大端写作 12 34
```

### 3.2 小端为什么叫“小端”

小端把最低有效字节放在较小的地址或报文中较早的位置：

```text
地址/偏移：  0     1
小端内容：  34    12
```

读取时不能把 `34 12` 直接按书写顺序理解为 `0x3412`；如果协议声明这是小端，它代表的仍然是 `0x1234`。

### 3.3 大小端不改变数值

`0x1234` 是一个数值。大端或小端只是这个数值拆成字节后的排列方式。

```text
大端字节 12 34  ──按大端解释──→ 0x1234
小端字节 34 12  ──按小端解释──→ 0x1234
```

如果用错误的顺序解释，就会得到不同数值：

```text
收到字节：12 34
按大端解释：0x1234 = 4660
按小端解释：0x3412 = 13330
```

## 4. 大小端必须说明“针对什么”

“这个协议是大端”这句话通常不够精确。一个协议可能在不同层次使用不同顺序：

1. 一个字节内部的 bit 发送顺序；
2. 16 位字段的字节顺序；
3. 32 位字段中两个 16 位寄存器的顺序；
4. CRC 数值拆成两个字节后的顺序；
5. CPU 内存中的存储顺序。

WireLink/Modbus RTU 就同时存在多种顺序：

| 对象 | 当前顺序 |
|---|---|
| UART 一个字节内的 bit | 通常 LSB 先发送 |
| Modbus 16 位地址、数量、寄存器值 | 高字节在前，即大端 |
| Modbus CRC 的两个字节 | 低字节在前 |
| 本项目多数 32 位值的两个寄存器 | 高 16 位寄存器在前 |
| 当前报警的两个寄存器 | 协议逻辑顺序 `[514, 513]` |

因此不能因为 CRC 低字节先发送，就认为整个 Modbus 报文都是小端。

## 5. Modbus 中的 16 位大端字段

Modbus 请求中的起始地址、数量和普通寄存器值都是 16 位字段，按高字节在前传输。

### 5.1 起始地址示例

地址 `0x0100`：

```text
高字节 = 01H
低字节 = 00H
报文字节 = 01 00
```

地址 `0x0311`（十进制 785）：

```text
高字节 = 03H
低字节 = 11H
报文字节 = 03 11
```

### 5.2 寄存器数量示例

读取 3 个寄存器：

```text
数量值 = 0x0003
高字节 = 00H
低字节 = 03H
报文字节 = 00 03
```

### 5.3 03H 请求示例

```text
03 03 01 00 00 03 05 D5
```

分解：

```text
03       从机地址
03       功能码
01 00    起始地址，大端，表示 0x0100
00 03    数量，大端，表示 3
05 D5    CRC，低字节在前
```

同一帧中：

- `01 00` 和 `00 03` 是普通 16 位字段，采用高字节在前；
- `05 D5` 是 CRC 字段，采用低字节在前。

### 5.4 03H 响应寄存器示例

假设响应数据部分为：

```text
12 34 AB CD
```

每两个字节表示一个 16 位寄存器：

```text
第一个寄存器 = (12H << 8) | 34H = 1234H
第二个寄存器 = (ABH << 8) | CDH = ABCDH
```

代码使用：

```csharp
BinaryPrimitives.ReadUInt16BigEndian(bytes);
```

如果错误地按小端解析：

```text
12 34 → 3412H，而不是 1234H
AB CD → CDABH，而不是 ABCDH
```

## 6. CRC 为什么是低字节在前

Modbus RTU 的 CRC-16 计算结果是一个 16 位数，但协议规定放入帧尾时先放低字节，再放高字节。

标准示例：

```text
参与 CRC 的字节：01 03 00 00 00 0A
CRC 数值：       0xCDC5
CRC 高字节：     CDH
CRC 低字节：     C5H
报文帧尾：       C5 CD
```

因此：

```text
CRC 数值的书写：CDC5
线路上的字节：  C5 CD
```

WireLink 的实现：

```csharp
frame[^2] = (byte)(crc & 0xFF); // 低字节
frame[^1] = (byte)(crc >> 8);   // 高字节
```

CRC 字段的低字节在前是 Modbus RTU 的明确规则，不会改变地址、数量和寄存器值的大端顺序。

## 7. 高字与低字

32 位整数可以拆成两个 16 位“字”（word）：

```text
数值：0x12345678
      └─1234─┘└─5678─┘
        高字     低字
```

- 高字（高 16 位）：`0x1234`
- 低字（低 16 位）：`0x5678`

提取：

```text
高字 = (value >> 16) & 0xFFFF
低字 = value & 0xFFFF
```

组合：

```text
value = (高字 << 16) | 低字
      = (0x1234 << 16) | 0x5678
      = 0x12345678
```

C# 示例：

```csharp
uint value = 0x12345678;
ushort highWord = (ushort)(value >> 16);     // 0x1234
ushort lowWord = (ushort)(value & 0xFFFF);  // 0x5678

uint restored = ((uint)highWord << 16) | lowWord;
```

## 8. 32 位寄存器为什么还有“字序”

一个 Modbus 寄存器只有 16 bit。保存一个 32 位值需要两个寄存器，因此除了寄存器内部的字节序，还必须知道两个寄存器谁在前。

假设数值为：

```text
0x12345678
```

每个 16 位寄存器内部均使用大端：

```text
高字寄存器 0x1234 → 线路字节 12 34
低字寄存器 0x5678 → 线路字节 56 78
```

但两个寄存器可以有两种顺序：

### 8.1 高字在前

```text
第一个寄存器：1234H
第二个寄存器：5678H
线路数据：12 34 56 78
组合结果：0x12345678
```

代码：

```csharp
uint value = ((uint)firstRegister << 16) | secondRegister;
```

### 8.2 低字在前

```text
第一个寄存器：5678H
第二个寄存器：1234H
线路数据：56 78 12 34
组合结果仍应为：0x12345678
```

代码：

```csharp
uint value = ((uint)secondRegister << 16) | firstRegister;
```

这叫**寄存器顺序**或**字序**，不要和单个寄存器内部的字节序混淆。

## 9. WireLink 中的 32 位字序

当前项目确认：协议定义中排在前面的寄存器通常是高 16 位，后面的寄存器是低 16 位。

### 9.1 普通连续地址

例如高精度电流 Ia 使用地址 336、337：

```text
register[336] = 高 16 位
register[337] = 低 16 位

value = (register[336] << 16) | register[337]
```

假设：

```text
register[336] = 0001H
register[337] = 2345H

组合原值 = 00012345H
```

如果字段倍率是 `×0.01`：

```text
显示值 = 0x00012345 × 0.01
       = 74565 × 0.01
       = 745.65 A
```

### 9.2 当前报警的特殊顺序

当前报警在协议表中的逻辑顺序是 `[514, 513]`：

```text
register[514] = 高 16 位
register[513] = 低 16 位

alarm = (register[514] << 16) | register[513]
```

假设：

```text
register[513] = 5678H
register[514] = 1234H
```

通信时按连续地址收到：

```text
地址 513：56 78
地址 514：12 34
线路数据：56 78 12 34
```

但业务组合必须按协议逻辑：

```text
高字 = register[514] = 1234H
低字 = register[513] = 5678H
结果 = 12345678H
```

因此不能看到地址 513 在前，就自动认为它是高字。地址顺序和数值权重不是同一个概念。

## 10. UART 位序不是 Modbus 字节序

UART 通常把一个字节的最低有效位先发送。以字节 `03H` 为例：

```text
字节数值：0000 0011
bit7                       bit0
 │                          │
 0    0    0    0    0    0    1    1

UART 数据位发送顺序：
bit0, bit1, bit2, bit3, bit4, bit5, bit6, bit7
 1     1     0     0     0     0     0     0
```

8N1 完整字符：

```text
[起始位0][1][1][0][0][0][0][0][0][停止位1]
```

接收端 UART 会把这些位重新组成字节 `03H`，软件通常不会直接处理线路 bit。

因此下面两件事可以同时成立：

- UART 在一个字节内部按 LSB first 发送；
- Modbus 的 16 位地址按高字节在前发送。

例如地址 `0x0100`：

```text
Modbus 决定字节顺序：01 00
UART 再分别发送：
    字节 01H：bit0 → bit7
    字节 00H：bit0 → bit7
```

UART 不会把 Modbus 字节顺序从 `01 00` 改成 `00 01`。

## 11. CPU 内存字节序与线路字节序

很多常见 CPU 使用小端内存。例如一个 16 位变量值为 `0x1234`，其内存可能是：

```text
低地址：34
高地址：12
```

但这不代表发送到 Modbus 时也应直接发送 `34 12`。协议编码必须显式转换为规定的线路字节序：

```text
CPU 内部值：0x1234
Modbus 大端编码：12 34
```

WireLink 使用 `BinaryPrimitives` 明确指定协议字节序，而不是依赖当前 CPU：

```csharp
BinaryPrimitives.WriteUInt16BigEndian(buffer, value);
BinaryPrimitives.ReadUInt16BigEndian(buffer);
```

这样代码在小端或大端 CPU 上都会产生相同的 Modbus 报文。

不建议在协议代码中直接使用与 CPU 字节序绑定的转换方式，然后假定所有运行环境都相同。

## 12. 有符号数与字节序

字节序只决定字节排列，不决定整数是否有符号。

同样两个字节：

```text
FF FE
```

按大端组合得到 16 位二进制：

```text
1111 1111 1111 1110
```

解释为：

```text
uint16：65534
int16：-2（补码）
```

所以解析一个字段至少需要知道：

1. 字节序；
2. 位宽；
3. 有符号或无符号；
4. 倍率和单位。

例如协议中的 `int16 × 0.01`，必须先按大端还原 16 位，再按有符号补码解释，最后乘 `0.01`。

## 13. BCD 与字节序

BCD 不是普通二进制整数。一个 BCD 字节用两个 4-bit 半字节分别保存十进制数字：

```text
BCD 0x26：
高半字节 2
低半字节 6
表示十进制 26，而不是普通二进制的 38
```

寄存器仍先按 Modbus 大端得到高、低两个字节，然后再根据协议定义解释每个字节。

例如：

```text
寄存器原值：0x2607
线路字节：26 07
协议定义：高字节为年，低字节为月

年 BCD 26 → 2026
月 BCD 07 → 7
```

这里同时涉及：

- Modbus 寄存器字节序：`26` 在前、`07` 在后；
- 字段布局：高字节是年，低字节是月；
- BCD 解码：`26H` 表示十进制 26。

三者不能用同一个“大端/小端”概念代替。

## 14. 常见错误

### 14.1 把高字节理解成“先收到的字节”

错误。高字节描述数值权重；它是否先收到由协议字节序决定。

```text
0x1234 的高字节永远是 12H
大端传输：12 34，高字节先收到
小端传输：34 12，高字节后收到
```

### 14.2 把 CRC 的低字节在前推广到全部字段

错误。Modbus 的普通 16 位字段是高字节在前，只有 CRC 的两个字节按低字节在前。

### 14.3 把 UART 的 LSB first 当成小端

错误。UART LSB first 描述一个字节内部的位发送顺序；大小端描述多字节值中各字节的顺序。

### 14.4 把地址顺序当成高低字顺序

错误。多数设备把低地址作为高字，但这不是由 Modbus 强制规定的。必须查设备寄存器表。

WireLink 的 `[514, 513]` 就说明高字可能位于更高的寄存器地址。

### 14.5 十六进制字符串直接反转

不能在没有层次概念的情况下把 `12345678` 简单反转。

可能的交换包括：

```text
交换字节：78 56 34 12
交换16位字：56 78 12 34
每个16位字内部交换字节：34 12 78 56
保持原顺序：12 34 56 78
```

必须先确认协议规定的是字节序、字序，还是两者都需要转换。

## 15. 快速判断方法

拿到一段协议数据时，按以下顺序确认：

1. 找一个已知值，例如已知电压为 230、地址为 `0x0100`。
2. 确认字段宽度，是 8、16 还是 32 bit。
3. 对 16 位字段确认两个字节谁在前。
4. 对 32 位字段先确认每个寄存器内部字节序，再确认两个寄存器的字序。
5. 单独确认 CRC 顺序，不要套用数据字段规则。
6. 确认有符号、无符号、BCD、位域或浮点类型。
7. 最后应用倍率和单位。

示例：收到两个字节 `00 E6`，协议说明为 `uint16`、大端、单位 V、倍率 `×1`：

```text
大端组合：(00H << 8) | E6H = 00E6H
十进制：230
倍率：230 × 1
结果：230 V
```

如果错误按小端解释：

```text
E600H = 58880 V
```

不合理的结果通常是字节序或倍率错误的重要信号。

## 18. 总结

高字节和低字节描述一个整数中各字节的**数值权重**；大端和小端描述这些字节的**排列顺序**。在 WireLink 使用的 Modbus RTU 中，地址、数量和每个 16 位寄存器按高字节在前传输，CRC 按低字节在前传输；32 位业务值还需要额外按照设备寄存器表确定高字和低字的寄存器顺序。UART 的 LSB first 只是一个字节内部的线路位序，不能替代或改变 Modbus 的字节序定义。
