# decimal scale：如何取出倍率的小数位数

本文说明 WireLink 如何根据协议倍率（例如 `×0.1`、`×0.01`）决定界面上显示几位小数，以及 `DecimalDigits` 两行代码在做什么。

相关代码：`src/WireLink.Core/Registers/RegisterParser.cs` 中的 `Scale` 与 `DecimalDigits`。

相关文档：

- [协议解析与未确认规则](protocol.md)
- [高字节、低字节与大小端说明](byte-order-guide.md)

## 1. 问题从哪里来

协议里很多测量值不是直接显示寄存器原码，而是 **原值 × 倍率**。例如：

```text
寄存器原值 raw = 123
倍率 multiplier = 0.1
显示值 = 123 × 0.1 = 12.3
```

解析器里对应这段逻辑：

```csharp
var scaled = raw * multiplier;
var digits = DecimalDigits(multiplier);
scaled.ToString(digits == 0 ? "0" : $"F{digits}", CultureInfo.InvariantCulture);
```

`ToString("F2")` 表示固定 2 位小数，`ToString("0")` 表示整数。因此必须先知道：**这个倍率小数点后面有几位**。

`DecimalDigits` 的唯一职责就是回答这个问题。它不算数学上的“最短小数展开”，而是读取 `decimal` 内部已经存好的 **scale** 字段。

## 2. 不要从字符串里数小数点

下面这些做法看起来直观，但都不合适：

| 做法 | 问题 |
|------|------|
| `multiplier.ToString().Split('.')[1].Length` | 受当前区域格式影响；`1.0` 可能打成 `1`；`0.10` 和 `0.1` 结果不同或丢失 |
| 循环 `while (x != Math.Truncate(x)) { x *= 10; n++; }` | 对 `decimal` 多余，且容易和二进制浮点的 `double` 搞混 |
| 固定写死 `"F2"` | 有的字段是 `×0.1`，有的是 `×0.01`，有的是 `×10`，精度不一致 |

正确做法是利用事实：C# 的 `decimal` **自己就记住了小数位数**。

## 3. decimal 在内存里怎么存

`decimal` 不是 IEEE 754 浮点（`float`/`double`）。一个值被拆成：

```text
数值 = 整数部分 × 10^(-scale)
```

先存一个最多 96 位的整数，再单独记「小数点往左移了几位」。这个「几位」就叫 **scale**，范围是 0～28。

| 字面量 | 整数部分 | scale | 还原 |
|--------|----------|------:|------|
| `0.1m` | 1 | 1 | 1 × 10⁻¹ = 0.1 |
| `0.01m` | 1 | 2 | 1 × 10⁻² = 0.01 |
| `0.10m` | 10 | 2 | 10 × 10⁻² = 0.10 |
| `10m` | 10 | 0 | 10 × 10⁰ = 10 |
| `-0.1m` | 1（符号另存） | 1 | −0.1 |

注意：`0.1m` 和 `0.10m` **数值相等**，但 scale 不同。`decimal` 会保留字面量里写了几位小数。协议目录里的倍率一般写成 `0.1m` / `0.01m`，scale 与协议精度一致。

## 4. GetBits 的四个 int

`decimal.GetBits(value)` 返回长度为 4 的 `int[]`：

```text
bits[0]  整数部分的低 32 位
bits[1]  整数部分的中 32 位
bits[2]  整数部分的高 32 位
bits[3]  标志字（不是数值本身）
```

对于常见的小倍率，整数部分很小，只占用 `bits[0]`。真正要用的是 `bits[3]`。

### 4.1 标志字 bits[3] 的位布局

32 位从高到低：

```text
 bit  31              23        16 15                   0
     [符号][  未用 7 位  ][  scale  ][     未用，必须为 0     ]
      1 bit               8 bit
```

- **bit16～bit23**：scale（0～28）
- **bit31**：符号。`1` 表示负数
- 其余位必须为 0

这和从整数里拆高/低字节是同一类操作：权重在数值里已经排好，用移位和掩码取出某一段。

### 4.2 实测对照

| 值 | `bits[0]` | `bits[3]` | scale | 符号 |
|------|----------:|------------------|-----:|-----:|
| `0.1m` | 1 | `0x00010000` | 1 | 0 |
| `0.01m` | 1 | `0x00020000` | 2 | 0 |
| `0.10m` | 10 | `0x00020000` | 2 | 0 |
| `10m` | 10 | `0x00000000` | 0 | 0 |
| `-0.1m` | 1 | `0x80010000` | 1 | 1 |

`0x00010000` 只有 bit16 为 1，scale 字段因此等于 1。  
`0x80010000` 额外把 bit31 置 1（负数），scale 仍然是 1。换算过程见下一小节。

### 4.3 十六进制怎么对上「第 16 位」

`0x00010000` 不是“第 16 个十六进制数字”，而是一个 32 位整数。每一位 hex 对应 **4 个 bit**，bit **从右边（最低位）从 0 开始数**。

8 个 hex 位刚好 32 bit：

```text
hex：     0    0    0    1    0    0    0    0
bit：   28-31 24-27 20-23 16-19 12-15  8-11  4-7   0-3
```

中间那个 `1` 占的是 **bit16～bit19**。一个 hex `1` 的二进制是 `0001`，写进这 4 位时，**最低的那一格**才是 1：

```text
bit19 bit18 bit17 bit16
  0     0     0     1      ← 这就是「第 16 位为 1」
```

把整串展开：

```text
bit位置  31                16 15                 0
         |                 |  |                  |
二进制    0000 0000 0000 0001 0000 0000 0000 0000
hex      0    0    0    1    0    0    0    0
                           ↑
                         bit16 = 1
```

另一种记法：第 n 位为 1，就是把 1 左移 n 位。

```text
1 << 16  =  65536  =  0x10000  =  0x00010000
```

所以看到 `0x00010000`，可以直接读成「只有 bit16 亮着」。

scale 存在 bit16～bit23。这里只有 bit16 = 1，其余为 0，等价于：

```text
scale = 00000001₂ = 1
```

同理 `0x00020000`：

```text
1 << 17  =  0x20000  =  0x00020000
```

bit17 = 1，落在同一段 scale 里：

```text
bit23 ... bit16
  0  0  0  0  0  0  1  0   =  2
```

因此 `0.01m` 的 scale 是 2。`>> 16` 正是把这段 8 位移到最右边，变成普通整数 1 或 2。

## 5. 两行代码逐步拆开

```csharp
private static int DecimalDigits(decimal multiplier)
{
    var bits = decimal.GetBits(multiplier);
    return (bits[3] >> 16) & 0x7F;
}
```

以 `multiplier = 0.01m` 为例。`bits[3] = 0x00020000`：

```text
十六进制：  0x00020000
二进制：    0000 0000  0000 0010  0000 0000  0000 0000
                       ^^^^^^^^
                       scale 在 bit16～23，这里是 2
```

### 第一步：`>> 16`

右移 16 位，把 scale 挪到最低字节：

```text
0x00020000 >> 16  =  0x00000002  =  2
```

对 `-0.1m`：

```text
0x80010000 >> 16  =  0x00008001
```

低位已经出现 `1`（scale），高位还可能带着符号移位后的残留，所以不能直接把右移结果当成 scale。

### 第二步：`& 0x7F`

`0x7F` 的二进制是 `0111 1111`，只保留最低 7 位：

```text
0x00000002 & 0x7F  =  2
0x00008001 & 0x7F  =  1
```

scale 最大为 28，7 位足够表示。掩码的作用是丢掉符号等无关位，只留下小数位数。

（规范里 scale 占 8 位，用 `& 0xFF` 同样正确。当前代码用 `0x7F`，对合法 `decimal` 结果相同。）

## 6. 再接到显示格式

`Scale` 用取到的位数生成格式串：

```text
digits == 0  →  "0"     →  整数，例如 120
digits == 1  →  "F1"    →  一位小数，例如 12.3
digits == 2  →  "F2"    →  两位小数，例如 1.23
```

完整数据流：

```text
寄存器原值 123
        │
        │  × multiplier
        ▼
   decimal 12.3
        │
        │  DecimalDigits(0.1m) → 1
        │  ToString("F1")
        ▼
   界面字符串 "12.3"
```

这样显示精度跟协议倍率一致，而不是依赖 `decimal.ToString()` 默认是否省略末尾 0。

## 7. 手算练习

给定 `bits[3]`，写出 scale：

| `bits[3]` | 计算 | scale |
|-----------|------|------:|
| `0x00000000` | `(0 >> 16) & 0x7F` | 0 |
| `0x00030000` | `(3 >> 0 的感觉：先 >>16 得到 3)` | 3 |
| `0x80020000` | 右移后低位为 2，掩码去掉符号 | 2 |

对应字面量分别是整数、`0.001m`、`-0.01m` 这一类值。

在 C# 里可以自己打印：

```csharp
var bits = decimal.GetBits(0.01m);
Console.WriteLine($"bits[3]=0x{bits[3]:X8}");
Console.WriteLine($"scale={(bits[3] >> 16) & 0x7F}");
```

## 8. 和本项目的对应关系

- 寄存器目录用 `decimal multiplier` 描述 `×N`（见 `RegisterCatalog` / `RegisterDefinition.Multiplier`）。
- `ValueTransform.Multiply` 走 `RegisterParser.Scale`。
- `Scale` 调用 `DecimalDigits`，再按 `F{n}` 格式化显示值和公式说明里的 `raw × multiplier`。
- 漏电、频率等协议字段常用 `×0.01`，电流类字段也可能是 `×1` 或变比相关规则；位数必须跟定义里的倍率走，不能全局写死。

## 9. 小结

1. `decimal` = 整数 × 10^(−scale)；scale 就是小数位数。
2. `GetBits` 的 `bits[3]` 在 bit16～23 存放 scale，bit31 存放符号。
3. `(bits[3] >> 16) & 0x7F` 只是把这段字段取出来。
4. 解析器拿这个位数生成 `F1`/`F2`/`0`，让界面精度等于协议倍率精度。
