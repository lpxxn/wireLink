# 协议解析说明

## Modbus RTU

串口固定 8N1、无流控。支持 03H 和 06H；CRC16 低字节在前。03H 单次寄存器数量限制 1～125。每帧校验从机地址、功能码、字节数、总长度和 CRC。超时或 CRC 错误重试一次；02/03/04 等设备异常直接返回。

默认请求超时 1000 ms，可在高级通信设置中调整；设备没有在超时时间内响应时按通信失败处理。暂不等待设备协议补充专用响应时序或重试间隔。RTU 请求间应用至少 3.5 字符静默期（定义、公式与代码见 [link-layer-and-read-register.md § 3.4](link-layer-and-read-register.md#34-帧间静默与-35-个字符时间)）。设备地址由用户在 1～255 内输入；地址不正确或没有对应设备时，连接测试按通信失败处理。地址 0 不用于读操作。

## 地址行规则

- 下一行只有地址：该地址是上一逻辑字段的附加寄存器，例如 336/337 只产生“高精度电流 Ia”一个显示项。
- 下一行地址为空：仍是同一寄存器内的字节或位段含义，不发起额外读取。
- 地址数组保持协议顺序，不能排序；当前报警是 `[514,513]`。

## 数值规则

- 单寄存器内部高字节在前。
- uint32 的寄存器顺序已确认：定义中排在前面的寄存器是高 16 位，后面的是低 16 位。例如 336 高、337 低；当前报警按协议表顺序为 514 高、513 低。主程序固定使用 `HighWordFirst`，不在页面提供字序设置；核心解析器仍保留 `LowWordFirst` 测试能力，Debug 日志始终记录两个原始寄存器。
- `×N` 为原值乘 N；百分数字段直接使用原始值，显示为紧邻数值的 `%`，例如原值 35 显示为 `35%`。
- 电流变比只允许 1 或 2。BW1 的额定电流序值 ≤10 时为 1，否则为 2；BW3 的序值 ≤11 时为 1，否则为 2。
- 当前暂按寄存器 787 返回“额定电流序值”实现。用户在高级通信设置中选择 `BW1 的控制器` 或 `BW3 的控制器`，软件用相应的额定电流表把序值映射为安培值，再按上述阈值计算电流变比。
- `CurrentRatioRule` 固化 BW1/BW3 的序值—额定电流表和变比边界。序值超出所选控制器的表格范围时，该字段显示原值和解析警告。
- 5.5 中“×1 或 ×2 注1”的电流事件也使用“控制器系列 + 787 序值”计算；寄存器 788 不参与计算。漏电仍为 `×0.01`，频率为 `×0.01`，百分比使用原值。
- 这是实机连接前的暂定解释；如果设备实际在 787 返回额定电流安培值，应根据实机结果调整。
- 512.bit3 是故障跳闸标志，优先于 512.bit2 报警标志：bit3=1 时 515～523 按故障解析；否则在 bit2=1 时按报警解析。
- 5.5.2 的 `Int=516` 是当前报警数据地址。报警只有数据 0 有效：当前报警使用 516，517～523 为空；历史报警对应使用 772，773～779 为空。软件仍批量读取完整区间，但这些空字段不解析原始值。
- 5.5.1 的故障数据 3 暂不解析事件对应的保护设置、倍率和单位；当前地址 519、历史地址 775 直接显示寄存器十进制原始值，Debug 日志同时保留十六进制原值。
- 512 未设置故障或报警标志时，515 显示“无当前故障/报警”，516～523 留空并视为正常状态，不产生协议警告。故障或变位事件中没有专门计算规则的附加数据直接显示十进制原始值。
- 非法 BCD、未知枚举和保留值只影响当前字段，不使整批失败。

## 读取区间

设备：256～258、268～270、279、336～343、352～357、432～433、512～523，加隐藏读取 787 额定电流序值。279“当前热容”按百分比原值显示并追加 `%`。连接测试读取 256 一个寄存器。

故障：785 的低 8 位是记录类型（0=故障、1=报警、2=变位），高 8 位是“指定要读取第几条记录”（0～15，0 表示最近的一条数据），写入值为 `(第几条记录 << 8) | 记录类型`。例如故障第 3 条记录=`0x0300`、报警第 3 条记录=`0x0301`、变位第 3 条记录=`0x0302`。故障数据页可选择记录类型和第几条记录；“立即读取”按当前选择编码并用 06H 写入 785，785 不允许使用 10H 功能码。软件校验 06H 回显后等待约 100 ms，再分别读取 768～787 和 1031“总操作次数”，两者互不影响；任一读取失败时仍展示另一部分的成功数据。表格展示/导出这些字段，其中 787 会按所选控制器映射成额定电流。

故障、报警、变位共用事件记录地址，但解析有区别。三种记录类型统一读取事件记录区：768～770 合并为“故障记录时间”，780～782 合并为“本次上电时间”，均按 BCD 解析并显示为 `yyyy-MM-dd HH:mm:ss`；771 按 5.4，772～779 按 5.5。选择类型 2 时也按相同地址读取和展示，不再视为缺少独立数据结构。软件以所选控制器解释 787，并用它计算相关电流值。根目录 README 的“待补充协议规则”是剩余问题清单。

## 故障记录类型、第几条记录与 06H/03H 的关系

5.5.1/5.5.2 中“同一个数据序号为何有多种含义”、事件类型与数据 0～7 的完整对应关系，参见 [协议 5.5 事件数据对应关系与代码处理](event-data-5.5-mapping.md)。

### 两个界面参数查什么

故障数据页的两个参数共同指定设备中的一条历史事件记录：

| 界面参数 | 协议位置 | 允许值 | 含义 |
|---|---|---:|---|
| 记录类型 | 寄存器 785 的 bit0～bit7（低 8 位） | 0～2 | 0=故障跳闸记录，1=报警记录，2=变位记录 |
| 第几条记录 | 寄存器 785 的 bit8～bit15（高 8 位） | 0～15 | 指定要读取该类型中的第几条记录；0 表示最近的一条数据 |

也就是协议原文中的：

```text
L：指定要读取的记录类型(char)  → 低 8 位
H：指定要读取第几条记录(char)  → 高 8 位
```

选择值的编码公式是：

```text
selector = (第几条记录 << 8) | 记录类型
```

示例：

| 界面选择 | 类型值 | 第几条记录值 | 写入 785 的值 |
|---|---:|---:|---:|
| 故障，第 0 条记录 | `00H` | `00H` | `0000H` |
| 故障，第 3 条记录 | `00H` | `03H` | `0300H` |
| 报警，第 3 条记录 | `01H` | `03H` | `0301H` |
| 变位，第 3 条记录 | `02H` | `03H` | `0302H` |
| 变位，第 15 条记录 | `02H` | `0FH` | `0F02H` |

这里严格按协议说法是“第几条记录 0～15”。协议工作人员已确认：**第 0 条表示最近的一条数据**。

### 为什么不能只用 03H 读取

03H 只能读取寄存器，不能告诉设备“接下来要看哪一种、哪一条记录”。

设备协议只提供一套共享的历史记录读取区：

```text
768～770：记录时间
771：记录相别和类型
772～779：记录数据 0～7
780～782：本次上电时间
783～787：版本、状态、选择器、框架和额定电流等
```

故障、报警、变位以及第几条记录 0～15 并没有各自独立的读取地址。寄存器 785 相当于一个“记录选择器”或“游标”：

```text
先设置 785：告诉设备要哪种记录、要读取第几条记录
再读取 768～787：取得设备放入共享读取区的那条记录
```

因此完整流程是：

```text
用户选择 类型 + 第几条记录
    ↓
组合 selector = (第几条记录 << 8) | 类型
    ↓
06H 写入寄存器 785，设置记录选择器
    ↓
等待设备准备所选记录（建议约 100 ms，项目默认 100 ms）
    ↓
03H 读取寄存器 768～787，取得记录内容
    ↓
03H 独立读取 1031，取得总操作次数
```

06H 不是在写故障记录内容，也不会修改历史事件本身；它只是在写“要读取哪条记录”的选择条件。真正读取数据仍然使用 03H。

### 原始文档在哪里说明

原始协议表中 785 标为 `R/W`，协议工作人员已补充确认：**785 地址只允许 06H 功能码，不允许使用 10H 功能码**。当前流程由以下规则组成：

1. 通讯地址表的事件记录区把地址 **785** 定义为：

   ```text
   L：指定要读取的记录类型
   H：指定要读取第几条记录
   类型：uint16
   属性：R/W
   变量格式：见 5.7
   ```

   对应 [tran.md](../../tran.md) 的事件记录地址表。

2. 原始协议 **5.7“指定要读取的记录”**规定：

   ```text
   bit0～bit7：0=故障跳闸记录，1=报警记录，2=变位记录
   bit8～bit15：上位机指定要读取哪条记录，范围 0～15
   ```

3. 原始协议 **3．预置单寄存器（06H）**规定：

   ```text
   功能码 06 允许用户改变单个寄存器的内容，
   控制器内部的任何可写的单寄存器都可以使用此功能码改变其值。
   ```

因为 785 被标为 `R/W`、内容又明确由“上位机指定”，并且工作人员确认 785 只能用 06H，所以项目使用 06H 写入选择值。之后等待约 100 ms，再用 03H 读取共享记录区。

注意：原协议虽然列出了 10H 功能码，但 785 不能用 10H 写入；这里必须使用 06H。

### 06H 写入示例

假设从机地址是 1，要读取“报警第 3 条记录”：

```text
记录类型：报警 = 1 = 01H
第几条记录：3 = 03H
selector = (03H << 8) | 01H = 0301H
寄存器地址 785 = 0311H
写入寄存器 785 的值 = 0301H
```

06H 下行报文：

```text
01 06 03 11 03 01 18 BB
│  │  └─地址─┘ └─数值─┘ └CRC┘
│  └ 功能码 06H
└ 从机地址 1
```

字段解释：

| 字节 | 含义 |
|---|---|
| `01` | 从机地址 |
| `06` | 写单个寄存器 |
| `03 11` | 寄存器地址 `0311H`，即十进制 785 |
| `03 01` | 写入值 `0301H`，即报警第 3 条记录 |
| `18 BB` | CRC 低字节、高字节 |

06H 正常响应应完整回显同一帧，表示设备接受了地址和值。随后项目读取 768～787，并按“报警”规则解释返回数据。

### 文档没有明确说明的部分

以下内容已由协议工作人员补充确认：

- 785 地址只允许 06H 功能码，不允许使用 10H 功能码；
- 写入 785 以后，最好延迟 100 ms 左右，给芯片读取数据的时间；
- 0～15 中，0 表示最近的一条数据；
- 故障、报警、变位共用地址，解析会有区别。

项目目前按以上规则实现；准备时间提供 0～2000 ms 设置，默认 100 ms。
